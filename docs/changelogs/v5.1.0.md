# Changelog v5.1.0

All notable changes in this release.

## [5.1.0]

> **The retry policy does what its name says, and the public API is smaller.** `SetRetryPolicy` waits before each retry, calls `OnRetry`
> before it, throws the last exception, can refuse a retry with `shouldRetry`, and now works when `ThrowIfException()` is not called.
> The configuration is published by interfaces (`IMapConfigurator`, `IKafkaConfigurator`...) and the implementations, with the internals
> of the expression engine, are `internal`. What you write with `AddFxMap(cfg => ...)` and `IDistributedMapper` does not change.

---

## Fixed

### Retry policy (`SetRetryPolicy`)

Read from the behavior of 5.0.0 with tests that failed the requests on purpose:

- **The delay was waited after a failed retry, not before it.** The first retry followed the failure at once, and after the last failure the
  policy still slept (and called `OnRetry`) before throwing. The delay is now waited **before** each retry, and nothing is waited after the last attempt.
- **`OnRetry` is called before each retry**, with the exception of the attempt that failed and the delay that is about to be waited. It is not called for
  the last failure. (Before, it was called after the wait, for the failure of a retry, and never for the first failure.)
- **The last exception is thrown.** The first one was.
- **With `ThrowIfException()` not called (the default), the retry policy did nothing:** the suppression of the errors was inside the retries and swallowed
  every failure before the policy saw it. A request that goes through a transport is now retried, and its error is suppressed only after the last attempt.
- **A caller that cancels stops the retries**, also while a delay is waited.

A request that a **local handler** answers (the service owns the data) is not retried, as it was not suppressed: its errors are thrown at once, as before
with `ThrowIfException()` off. (In 5.0.0 a local handler was retried.)

## Added

- **`shouldRetry`** in `SetRetryPolicy(retryCount, sleepDurationProvider, onRetry, shouldRetry)`: a `Func<Exception, bool>` that decides whether a failure is
  worth a retry; when it returns `false` the exception is thrown at once, without a delay. Without it every exception is retried (but not when the caller cancelled).

  ```csharp
  cfg.SetRetryPolicy(
      retryCount: 3,                                                  // retries after the first attempt (at most 4 attempts)
      sleepDurationProvider: n => TimeSpan.FromMilliseconds(          // waited BEFORE retry n (1 = the first retry)
          Random.Shared.Next(0, 200 * (1 << (n - 1)))),               // exponential backoff with jitter
      onRetry: (ex, delay) => logger.LogWarning(ex, "Retry in {Delay}", delay),
      shouldRetry: ex => ex is TimeoutException or IOException);      // retry only what can go away
  ```

- Tests of the retry policy: the number of attempts, when the delay is waited, `OnRetry`, `shouldRetry`, the exception that is thrown, cancellation, and the
  default (`ThrowIfException()` not called).

## Changed: what is public

The configuration is published by **interfaces**, as in FxLink, and the classes that implement it are `internal sealed`:

| Public (use these) | Was |
|---|---|
| `IMapConfigurator` | `MapConfigurator` |
| `IKafkaConfigurator`, `IRabbitMqConfigurator`, `ISqsConfigurator`, `IGrpcClientsConfigurator` | `KafkaConfigurator`, `RabbitMqConfigurator`, `SqsConfigurator`, `GrpcClientsConfigurator` |
| `IEfCoreConfigurator`, `IMongoDbConfigurator`, `IHotChocolateConfigurator` | `EfCoreConfigurator`, `MongoDbConfigurator`, `HotChocolateConfigurator` |
| `INatsConfigurator`, `IAzureServiceBusConfigurator` | `NatsClientSetting`, `AzureServiceBusClientSetting` |

`AddFxMap(cfg => ...)` and every `AddXxx(c => ...)` take the interface. The members that only read the settings (`ServiceHosts`, `NatsOption`, `MaxNestingDepth`,
`SupervisorOptions`, `ProfileConfigs`...) are not part of the interfaces. `ConfiguratorWrapped` (what `AddFxMap` returns, for `.AddEntityFrameworkCore(...)`
and `.AddMongoDb(...)`) keeps its members internal. The classes of options that you fill in a callback (`RabbitMqCredential`, `SqsCredential`,
`KafkaSslOptions`, `FxNatsOpts`) are still public.

These are **internal** now, as they are details of the implementation:

- The expression engine: the nodes of the tree (`FilterNode`, `FunctionNode`...), `Tokenizer`, `Token`, `ExpressionParser`, `ExpressionParseException`,
  `IExpressionNodeVisitor`, `LinqExpressionBuilder`, `ProjectionBuilder` and the contexts and results of the builders; `BsonProjectionBuilder` of MongoDB.
- `TypeAccessor`, `ITypeAccessor`, `PropertyAccessor<,>`, the delegates `GetEntityConfig`, `GetProfileConfig`, `GetTypeAccessor`, `MapperDelegates`,
  the helpers, `ReceivedPipelinesOrchestrator`, `RequestContextImpl`, `JsonSerializer`, `ServerSupervisor` (`IServerSupervisor` is still public),
  `NoOpQueryOfHandler`, `Recyclable` (not used), and the extension helpers (`Extensions`, `TypeExtensions`, `TaskExtensions`...).
- gRPC: the types that Grpc.Tools generates from the `.proto`, `GrpcServer`, `GrpcRequestClient`. NATS: `MessageRequestWrapped`. HotChocolate: `FieldContext`.

## Compatibility

For the usual use (`services.AddFxMap(cfg => ...)`, `IDistributedMapper`, profiles, entity configurations, `AddEntityFrameworkCore`, `AddMongoDb`, a transport
with a lambda) **nothing changes**: the lambda parameter is inferred, and it is the interface now. This is a minor version because of that, but a type that left
the public API breaks the code that names it, so look for these:

- Code that names a configurator type: `Action<MapConfigurator>`, `NatsClientSetting c`, `MongoDbConfigurator`... Use the interface (`Action<IMapConfigurator>`).
- Code that uses the expression engine (`ExpressionParser.Parse`, the nodes, `Tokenizer`, a visitor `IExpressionNodeVisitor`), `ServerSupervisor`, or the gRPC
  generated messages. There is no replacement; they were never meant to be called from outside.
- A package that was compiled against 5.0.0 and calls one of these must be compiled again (binary compatibility is not kept for the types that left).
- **Retry policy**: if you counted on the old behavior, check `OnRetry` (it receives the exception of the failed attempt and is called before the wait),
  the exception you catch after the retries (the last one), and that a local handler is no longer retried.

Still public on purpose: `IFluentProfileConfig`, `IFluentEntityConfig` and what `ProfileOf<T>` exposes (they are part of the signature of
`AddProfileConfig`), the interfaces for custom transports and providers (`IRequestClient`, `IRequestServer`, `IClientRequestHandler`, `IQueryOfHandler`,
`QueryHandlerBuilder`) and the exceptions.

## Migration

1. Build. If the compiler says that a type is inaccessible, replace it with its interface (table above).
2. If you call `SetRetryPolicy`, read the section on the retry policy and add `shouldRetry` for the failures that are not worth a retry.
