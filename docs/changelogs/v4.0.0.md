# Changelog v4.0.0

All notable changes in this release.

## [4.0.0]

> **Breaking release.** Entity configurations are validated when they are configured, `Id` / `DefaultProperty` are
> stored as selector lambdas, and the data provider API (`IIdConverter<TId>`, `QueryHandlerBuilder`, `IMapEntityConfig`,
> `ProjectionBuilder`, `RequestedIdAnswers`) changes shape. See the [Migration Guide](#migration-guide).
> 3.0.1 was never released: everything since 3.0.0 is in this version.

---

## Who is affected

| You... | Affected by |
|---|---|
| write entity configurations (`EntityConfigureOf<T>`) | [A1](#a1-an-entity-configuration-must-call-id-once-and-the-selector-must-read-the-entity), [A2](#a2-internal-entity-configurations-are-now-registered) |
| call `IDistributedMapper` | nothing breaks; [A3](#a3-idistributedmapper-has-a-new-overload) adds an overload |
| fake or implement `IDistributedMapper` | [A3](#a3-idistributedmapper-has-a-new-overload) |
| write a data provider or a custom `IQueryOfHandler` | [P1](#p1-iidconverter-is-generic-only-and-returns-listtid) to [P5](#p5-requestedidanswersalign) |
| only use FxMap with the EF Core / MongoDB / transports packages as they are | A1 and A2 at most |

## Breaking Changes: applications

### A1. An entity configuration must call `Id(...)` once, and the selector must read the entity

`Id(x => ...)` and `DefaultProperty(x => ...)` now keep their selector lambda and are checked **when the entity is
configured** (at `AddFxMap(...)`), not when the first request arrives.

| Situation | Before | Now |
|---|---|---|
| `Configure()` never calls `Id(...)` | failed on the first request that needed the id | `EntityIdNotConfigured` at startup |
| `Id(...)` or `DefaultProperty(...)` called twice | the last call silently won | `InvalidEntitySelector` ("declared more than once") |
| a selector that does not read the entity (`x => "always"`, `x => 5`) | accepted by `DefaultProperty`, failed later | `InvalidEntitySelector` ("does not read the entity") |
| a selector that is not a plain property (`x => x.Code + x.Site`) | `ArgumentException` | accepted (computed id or default property) |

**Before (3.x):**
```csharp
public class UserConfig : EntityConfigureOf<User>
{
    protected override void Configure()
    {
        DefaultProperty(x => x.Name);          // no Id: the first request fails
        UseDistributedKey<UserDistributedKey>();
    }
}
```

**After (4.0):**
```csharp
public class UserConfig : EntityConfigureOf<User>
{
    protected override void Configure()
    {
        Id(x => x.Id);                         // required, once
        DefaultProperty(x => x.Name);          // optional, once
        UseDistributedKey<UserDistributedKey>();
    }
}
```

Computed selectors are new and work with the EF Core provider (the filter is translated to the database):
```csharp
Id(x => x.Code + ":" + x.Site);                // the id of a request is "A:F1"
DefaultProperty(x => x.Name + " (" + x.Level + ")");
```
The MongoDB provider needs the name of a stored field, so it only accepts plain property selectors (`x => x.Code`) and
throws `NotSupportedException` for anything else.

### A2. Internal entity configurations are now registered

`AddEntitiesFromAssemblyContaining<T>()` and `AddEntitiesFromAssemblies(...)` scan **all** types of the assembly
(`DefinedTypes`), not only the public ones (`ExportedTypes`). An `internal` (or nested non-public) class that derives from
`EntityConfigureOf<T>` was ignored before and is registered now.

If you relied on a non-public configuration being ignored (shared assemblies, test helpers, abstract bases), either make it
`abstract` or an open generic (assembly scans only register closed concrete types), move it out of the scanned assembly,
or register the configurations you want explicitly with `AddEntityConfig<T>()`.

### A3. `IDistributedMapper` has a new overload

```csharp
Task MapDataAsync(object value, IContext context, CancellationToken token = default);
```
Callers are not affected. A class that **implements** `IDistributedMapper` (for example a hand-written fake in a test) must
add the overload:

```csharp
public sealed class FakeMapper : IDistributedMapper
{
    public Task MapDataAsync(object value, CancellationToken token = default) => Task.CompletedTask;
    public Task MapDataAsync(object value, IContext context, CancellationToken token = default) => Task.CompletedTask;
    // FetchDataAsync overloads as before
}
```
Mocks generated by a mocking library need no change.

What the overload does: the `IContext` carries headers and a `CancellationToken`. **Both** the caller's token and the
token of the context cancel the requests (they are linked), and the headers of the context are sent with every request.
`MapDataAsync(value, token)` behaves exactly as before.

## Breaking Changes: data providers and custom handlers

These only affect code that implements a data provider or a custom `IQueryOfHandler` (the EF Core and MongoDB packages
are already updated).

### P1. `IIdConverter` is generic only and returns `List<TId>`

`IIdConverter` (non-generic) is removed. `IIdConverter<TId>` is the only interface, `ConvertIds` returns `List<TId>` instead of
`object`, and `TId` is **invariant** (the `out` is gone because `List<T>` is invariant).

**Before (3.x):**
```csharp
public sealed class GuidConverter : IIdConverter<Guid>
{
    public object ConvertIds(string[] selectorIds) =>
        selectorIds.Where(id => Guid.TryParse(id, out _)).Select(Guid.Parse).ToArray();
}
```

**After (4.0):**
```csharp
public sealed class GuidConverter : IIdConverter<Guid>
{
    public List<Guid> ConvertIds(string[] selectorIds) =>
        [..selectorIds.Where(id => Guid.TryParse(id, out _)).Select(Guid.Parse)];
}
```
Registering an `IStronglyTypeConverter<TId>` (the usual way to support a custom id type) needs no change.

### P2. `MapEntityConfig` is `IMapEntityConfig` and exposes selectors

| 3.x | 4.0 |
|---|---|
| `MapEntityConfig.IdProperty` (`string`) | `IMapEntityConfig.IdPropertySelector` (`LambdaExpression`) |
| `MapEntityConfig.DefaultProperty` (`string`) | `IMapEntityConfig.DefaultPropertySelector` (`LambdaExpression`, may be `null`) |
| `MapperDelegates` returns `MapEntityConfig` | returns `IMapEntityConfig` |
| `EntityInfo(Type, Type, MapEntityConfig)` | `EntityInfo(Type, Type, IMapEntityConfig)` |
| `IFluentEntityConfig.IdPropertyName` / `DefaultPropertyName` | `IdPropertySelector` / `DefaultPropertyNameSelector` |

A provider that needs the **name** of the property (like the MongoDB provider) can read it from the selector:
```csharp
static string PropertyNameOf(LambdaExpression selector)
{
    var body = selector.Body;
    while (body is UnaryExpression { NodeType: ExpressionType.Convert } convert) body = convert.Operand;
    return body is MemberExpression { Expression: ParameterExpression } member
        ? member.Member.Name
        : throw new NotSupportedException($"Only property selectors are supported, got '{selector}'.");
}
```

### P3. `QueryHandlerBuilder` is a contract; resolve the implementation

`QueryHandlerBuilder<TModel, TKey>` no longer takes an `IServiceProvider` and no longer has protected members: it declares
three public abstract members. The implementation is `QueryHandlerBuilder<TModel, TId, TKey>`, registered by `AddFxMap`.
`FilterContext` and `FilterContext<TId>` are removed (the filter is a `List<TId>.Contains(id)` expression built internally).

**Before (3.x):**
```csharp
internal class MyHandler<TModel, TKey>(IServiceProvider sp)
    : QueryHandlerBuilder<TModel, TKey>(sp), IQueryOfHandler<TModel, TKey> { ... }

// inside: BuildFilter(query), BuildProjection(query), AnswerRequestedIds(query, rows)   (protected)
```

**After (4.0):**
```csharp
internal sealed class MyHandler<TModel, TKey>(IServiceProvider serviceProvider) : IQueryOfHandler<TModel, TKey>
    where TModel : class
    where TKey : IDistributedKey
{
    private readonly IMapEntityConfig _entityConfig = serviceProvider
        .GetRequiredService<MapperDelegates>()
        .Invoke(typeof(TModel), typeof(TKey));

    public async Task<ItemsResponse<DataResponse>> GetDataAsync(RequestContext<TKey> context)
    {
        var idType = _entityConfig.IdPropertySelector.Body.Type;
        var builder = (QueryHandlerBuilder<TModel, TKey>)serviceProvider.GetRequiredService(
            typeof(QueryHandlerBuilder<,,>).MakeGenericType(typeof(TModel), idType, typeof(TKey)));

        Expression<Func<TModel, bool>> filter = builder.BuildFilter(context.Query);
        var (projection, expressions) = builder.BuildProjection(context.Query);

        object[][] rows = await RunQueryAsync(filter, projection, context.CancellationToken);   // your data source
        var data = builder.AnswerRequestedIds(context.Query,
            ProjectionTransformer.TransformToArray(rows, expressions));
        return new ItemsResponse<DataResponse>(data);
    }
}
```

### P4. `ProjectionBuilder` takes selectors

The constructor taking property names and the static `ProjectionBuilder.Create(...)` are removed.

**Before (3.x):** `new ProjectionBuilder<User>("Id", "Name", getTypeAccessor)`

**After (4.0):**
```csharp
new ProjectionBuilder<User>(
    (Expression<Func<User, string>>)(x => x.Id),
    (Expression<Func<User, string>>)(x => x.Name),     // or null for no default property
    getTypeAccessor);
```
Selectors are not checked here: entity configurations validate them (A1). The id and default property can be any
expression over the entity.

### P5. `RequestedIdAnswers.Align`

`Align(requestedIds, rows, IIdConverter)` becomes `Align<TId>(requestedIds, rows, IIdConverter<TId>)`; the type argument is
inferred. A provider that only learns the id type at runtime (like the MongoDB one) uses the new overload that takes the
canonical id text itself:

```csharp
RequestedIdAnswers.Align(requestedIds, rows, text => canonicalIdTextOf(text));   // Func<string, string>
```

## Upgrade checklist

1. Every `EntityConfigureOf<T>` calls `Id(...)` exactly once (A1).
2. If you have non-public entity configurations in a scanned assembly, check that they are meant to be registered (A2).
3. If you fake `IDistributedMapper`, add the new overload (A3).
4. If you wrote a provider or a custom `IQueryOfHandler`: update `IIdConverter` (P1), `IMapEntityConfig` (P2),
   `QueryHandlerBuilder` and `FilterContext` (P3), `ProjectionBuilder` (P4) and `RequestedIdAnswers.Align` (P5).
5. Upgrade every `FxMap.*` package to 4.0.0 together.
