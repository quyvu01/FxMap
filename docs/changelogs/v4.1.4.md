# Changelog v4.1.4

All notable changes in this release.

## [4.1.4]

> **Security and fixes.** Every package is free of known vulnerable dependencies (the floors of MongoDB.Driver, HotChocolate and
> Microsoft.Extensions.Caching.Memory are raised), a field of a HotChocolate type that depends on a conditional rule is resolved
> with the right expression, and the Azure Service Bus client no longer leaks its connection.

---

## Fixed

### RabbitMQ

- **The consumer never worked again after the connection to the broker was lost.** The queue of the replies was declared without a name,
  so the broker chose one. A recovered connection declares the queue again with another name, but the requests kept the name in
  `ReplyTo`: the owner replied to a queue that no longer existed and every request timed out until the process restarted. The client now
  chooses the name of its reply queue (`fxmap-reply-<guid>`, exclusive, auto-delete), so the recovery declares the same queue. Found by a
  test that cuts the connection between the service and a real broker; the consumer works again about 10 s after the broker is back
  (the recovery interval of the connection is 10 s).

### Servers of the transports

- **A server could not be started again after it was stopped (NATS, SQS, Kafka).** The supervisor stops and starts the servers again with the
  strategies `OneForAll` and `RestForOne`, but `StopAsync` disposed the semaphore (NATS, SQS, Kafka) or the consumer (Kafka) of the server,
  and the next start failed with `ObjectDisposedException`. Nothing is disposed that a start needs; Kafka creates its consumer on each start.
  SQS no longer polls the same queue twice after a start that is repeated, and RabbitMQ closes the consumers that a start which failed half
  way left behind.

### Supervisor of the servers

- **After the restart of every server (`SupervisionStrategy.OneForAll`), a server that was running was reported as `Stopped`.** The run that
  the restart had cancelled read the token of the new run, took the cancellation for a failure and marked the server as stopped.
- **`RestForOne` restarted the wrong servers.** The servers "after" the failed one were taken in the order of a dictionary, not in the order
  of their registration.

### HotChocolate

- **A field that depends on a conditional rule was fetched with the wrong expression.** For each field, the resolver also fetched the
  chain of rules it depends on, with the raw expression of each rule. A conditional rule has no expression of its own (it is
  resolved for the request), so it was fetched with `null`, the default property of the entity. That was an extra request, and for a chain
  such as `UserId → ProvinceId (conditional) → ProvinceName` it gave a wrong value: the name of the user was used as the id of
  the province. The rule of the field itself is no longer fetched twice, and the conditional rules of the chain are resolved for the request.

### Azure Service Bus

- **The AMQP connection of the namespace was never closed.** The client was created by the container but held in a record that was
  not disposable, so disposing the container (a host that stops, a test) left the connection open. A namespace or an emulator has a quota
  of connections: the Service Bus tests of a whole run ended with `ConnectionsQuotaExceeded`. The wrapper of the client is now
  disposed with the container.

## Changed

### Dependencies without known vulnerabilities

`dotnet list package --vulnerable --include-transitive` is clean for every package of this release. The lower bounds of three
dependencies were raised, because the lowest version allowed brought a vulnerable package:

| Package | Dependency | Before | Now | Why |
|---|---|---|---|---|
| `FxMap.MongoDb` | `MongoDB.Driver` | 3.2.1 | **3.9.0** | 3.9.0 is the first driver that depends on SharpCompress 0.48.1 and Snappier 1.3.1: GHSA-6c8g-7p36-r338 (directory traversal, moderate) and GHSA-pggp-6c3x-2xmx (an infinite loop when decompressing Snappy data, high) |
| `FxMap.HotChocolate` | `HotChocolate.AspNetCore` | 15.1.1 | **15.1.14** | before 15.1.14, `HotChocolate.Language` has GHSA-qr3m-xw4c-jqw3 (a stack overflow on deeply nested documents, **critical**) |
| `FxMap.EntityFrameworkCore` | `Microsoft.Extensions.Caching.Memory` | 8.0.0 (through EF Core) | **8.0.1** | GHSA-qj66-m88j-hmgj (denial of service, high) |

An application that pins an older version of one of these packages has to upgrade it. The HotChocolate integration was tested with
15.1.14; that version can only dispose its request executor asynchronously (`DisposeAsync`), which matters only if you build a
container yourself and dispose it with `Dispose()`.

### Build and tests

- The Azure Service Bus tests (on the emulator) now have to pass, like the other transports, before the version is calculated and published.
- Samples and tests use fixed versions too (OpenTelemetry 1.19, `MongoDB.Bson` 3.9.0, the NuGet client packages 6.14.3 in the analyzer
  tests). The AutoMapper 14 of the benchmark project is the baseline of the comparison in the README and has GHSA-rvv3-g6hj-g44x; the audit
  warning is suppressed there with a comment (the project is never shipped). Upgrading AutoMapper means measuring again.
- The build has no warning: the analyzer release file uses the header format that the release-tracking analyzer expects (RS2007), and
  some unused usings were removed.

## Added

- **Kafka: `Partitions(n)` and `ReplicationFactor(n)`** in `AddKafka(...)`: the partitions of the request topic of each distributed key and the replication factor
  of the topics that FxMap creates (both were fixed at 1, which does not fit a cluster of several brokers or several instances of a service). The default
  stays 1; a topic that exists is not changed.
- **Tests of the HotChocolate integration (12)**: a real schema executed in process, with fields resolved from other services, a dependent
  field, only the requested fields fetched, one request for a whole list, a computed key, a conditional expression that reads the scope of
  the request (also in a chain), and expression errors with and without `ThrowIfException()`.
- A unit test that the Azure Service Bus client is closed when the container is disposed.

---

## Migration

Nothing to do, unless you pin `MongoDB.Driver` below 3.9.0, `HotChocolate.AspNetCore` below 15.1.14 or `Microsoft.Extensions.Caching.Memory` below
8.0.1: upgrade them.
