# Changelog v5.1.1

All notable changes in this release.

## [5.1.1]

> **Fixes found by testing every function of the expression language against real databases.** The same list of expressions (81 of them, with the values that
> `docs/expression.md` gives) was run through the LINQ builder, PostgreSQL (EF Core) and MongoDB. PostgreSQL answered all of them as documented;
> **MongoDB had four bugs**, the LINQ builder two, and the configuration two. Nothing to change in your code.

---

## Fixed

### MongoDB

- **`avg` answered the sum.** `Orders:avg(Total)` gave 4350 for orders of 1500, 350 and 2500 (the average is 1450), also inside a `groupBy`
  (`:avg(Total) as Avg`). The aggregates `sum`, `avg`, `min` and `max` now run the operator of MongoDB over the values of the property. As a consequence,
  `min`, `max` and `avg` of an empty collection are `null` (they gave the largest or the smallest `double`, or 0).
- **`any(condition)` and `all(condition)` gave wrong answers.** The properties of the condition were written as text (`"Status"`) instead of the field of the item
  (`"$$item.Status"`), so `Orders:any(Status = 'Pending')` was always false, `Orders:any(Total > 5000)` was always true (a text is greater than a number), and
  `Orders:all(Total > 400)` was true. `:any` and `:all` without a condition were right.
- **`endswith` failed the request** (`'$' by itself is not a valid FieldPath`), and **`contains` and `startswith` read the text as a regular expression**, so a `.` or a `+`
  in the value matched something else. The three use `$indexOfCP` and `$substrCP` now, and the value is taken as it is.
- **A collection projected from a field answered `{}`:** `Orders.{Number, Status}` read `Orders` as one object. The database now chooses: an array is mapped
  item by item, an object is read field by field (`$isArray`).

### Expression language (LINQ builder)

- **`Address?.City` threw `NullReferenceException`** when `Address` was null. The null test of `?.` was built on the object that holds `Address`, which is never null,
  not on `Address`. (`Address?.City ?? 'Unknown'` is the example of `docs/expression.md`.)
- **`&&` and `||` in a ternary were a parse error:** `Name = 'John' && Score > 80 ? 'Hit' : 'Miss'`. They are supported, with `&&` before `||`
  (a comma still separates the items of a projection).

### Configuration

- **`AddProfileConfig<T>()` and `AddEntityConfig<T>()` registered twice threw** "both 'X' and 'X' configure the same model". They are idempotent now, like
  `AddProfileConfigs(typeof(X))` was.
- **`ChannelPoolSize(0)` or a negative value of RabbitMQ was accepted** (a pool of no channel waits for ever); it is rejected with `ArgumentOutOfRangeException`.

## Tests

About 215 tests were added (1173 in the run on real infrastructure, was 957), and the line coverage went from 70.7% to 82.6% (MongoDB 55% to 89%, the MongoDB translation
43% to 90%, the LINQ builder 46% to 80%; generated gRPC code not counted):

- Every function (strings, dates, math, aggregates, `any`/`all`, filters, coalesce, ternary, projections, `distinct`, `groupBy`), in memory and, with the same cases, on
  MongoDB and PostgreSQL.
- The pipelines of the owner and of the client, custom expressions, strongly typed ids, `IMapConfigurator`, the activities of OpenTelemetry, the configuration of every transport
  (including that `FxNatsOpts` copies every option of the NATS client) and the message of every exception.

## Known limits

- The Azure Service Bus transport is covered only by the emulator job of the CI (13% on a machine without the emulator).
- Some code is not called by anything (`TaskExtensions.OrTimeout`/`OrCanceled`, `LeafImplementationFinder`, `Recyclable`); it is internal, and has no tests.

---

## Migration

Nothing to do. If you work around the old behavior of MongoDB (for example by computing an average yourself because `avg` was wrong), you can remove it.
