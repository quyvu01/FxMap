# Changelog v4.1.2

All notable changes in this release.

## [4.1.2]

> **Bug fixes found by running the data providers and the transports against real databases and brokers.** MongoDB now
> answers `Guid` ids and returns plain JSON, RabbitMQ keeps the headers of the context, gRPC honors `ThrowIfException()`
> whatever the order of the configuration, and Kafka no longer crashes the process when a service stops, sends the headers of the
> context and does not lose replies. The test suite now covers MongoDB, PostgreSQL, gRPC, NATS, RabbitMQ, SQS, Kafka and Azure
> Service Bus.

---

## Fixed

### MongoDB

- **A `Guid` id was never answered.** The filter found the document, but the id of the response was
  `BsonValue.ToString()` of the stored id (`UuidStandard:0x0a1b2c3d...`), not the Guid. The caller matches a response with
  the text it sent, and `RequestedIdAnswers` could not translate it either, so every row was dropped. A `string` or `int`
  id was not affected.
  The id of a response is now the text of the Guid (`0a1b2c3d-...`), and the id is answered under each spelling that was
  requested (upper case, without hyphens).
- **Values were returned as extended JSON.** `Orders:sum(Total)` came back as `{ "$numberDecimal": "4350.00" }`, an `ObjectId`
  as `{ "$oid": "..." }`, a date as `{ "$date": "..." }`. None of them can be deserialized into a `decimal`, a `string` or a
  `DateTime`, so the property was never filled (or the mapping threw with `ThrowIfException()`).
  Values are now plain JSON: numbers, strings, booleans, ISO dates, arrays and objects. A `Decimal128` that does not fit a
  `decimal` is returned as text. Values that were already plain (strings, ints, booleans, doubles) are unchanged.

### RabbitMQ

- **The headers of the context reached the owner as `"System.Byte[]"`.** RabbitMQ delivers string headers as UTF-8 bytes
  and the server called `ToString()` on the array. A header such as a tenant id was lost on this transport; it is now decoded.

### gRPC

- **`ThrowIfException()` had no effect on the clients when it was called after `AddGrpcClients(...)`**, which is the order of
  the samples. The flag was copied when the clients were registered, so an owner that could not be reached was answered
  with no rows and no error. The flag is read when a request is made.

### Kafka

- **The process crashed every time a service using Kafka stopped.** The supervisor cancels the consume loop and then stops the
  server, and the server disposed its consumer at once, while `Consume()` was still running on it (librdkafka does not survive
  that). The server now waits for the loop to return, closes the consumer and then disposes it.
- **The headers of the context were never sent.** Only the trace headers went with the request, so the owner never saw a
  tenant id or any other header. They are sent now.
- **A reply could be lost and the request then timed out.** The reply consumer started at `Latest`, but a consumer is assigned
  its partition a few seconds after it subscribes: a reply sent by a fast owner in the meantime was skipped. The reply topic
  belongs to the client alone, so it is read from the start.
- **Disposing a client waited 10 seconds and then threw.** Nothing cancelled its consume loop, and a task that had not
  completed was disposed.

## Added

- **Provider tests** (`test/FxMap.Tests/ProviderTests`): the same scenarios (string, `Guid` and `int` ids in several
  spellings, missing ids, navigation, aggregates, a missing nested object, the mapper end to end) against a real MongoDB and a
  real PostgreSQL.
- **Transport tests** (`test/FxMap.Tests/TransportTests`): an owner and a consumer in one process that only talk through the
  real transport, for gRPC (in process, always run), NATS, RabbitMQ, SQS, Kafka and Azure Service Bus (on its emulator). They
  check the values, the headers of the context, the error of the owner and the time-out when nobody answers.
- The tests that need a database or a broker are **skipped** unless `FXMAP_TEST_MONGO`, `FXMAP_TEST_POSTGRES`,
  `FXMAP_TEST_NATS`, `FXMAP_TEST_RABBITMQ`, `FXMAP_TEST_SQS`, `FXMAP_TEST_KAFKA` or `FXMAP_TEST_SERVICEBUS` is set (see `CONTRIBUTING.md`).
- The workflow has a `provider-tests` job (MongoDB 7, PostgreSQL 17) and a `transport-tests` job (RabbitMQ, LocalStack, NATS,
  Kafka) on net8, net9 and net10. Both are required before a version is published. A `servicebus-tests` job runs the Azure
  Service Bus tests on the emulator (`test/servicebus-emulator`, net10 only); it does not block the publish yet.
- The Expressions integration tests (`IntegrationTests.Expressions`, 63 tests) now run in CI: no workflow step matched their
  namespace before.

## Known limits

- **MongoDB: a computed id is not supported.** `Id(x => x.Mrn + x.Code)` throws `NotSupportedException` ("The MongoDB provider
  supports only property selectors...") when the first request arrives, not when the service starts. Only a property can be the
  `Id` and the `DefaultProperty` of a MongoDB entity.
- **gRPC:** the message of an exception of the owner is not sent to the consumer (it gets `StatusCode.Unknown`) unless
  `EnableDetailedErrors` is on in the owner.
- The Service Bus emulator runs on x64 only (not on an Apple Silicon machine), and its tests wait a fixed 25 seconds for the
  owner, which first tries (and fails) to create its queues through an administration API the emulator does not serve.

## Migration

Nothing to do. If a MongoDB consumer worked around the extended JSON (for example with a property of type `string` holding
`{ "$numberDecimal": ... }`), the property now receives the plain value.
