# Changelog v4.1.1

All notable changes in this release.

## [4.1.1]

> Conditional expressions in HotChocolate now run on the scope of the request. Documentation of how conditional
> expressions run, and internals exposed to the FxMap provider packages.

---

## Changed

- **HotChocolate: conditional expressions receive `RequestServices`** (the scope of the request) instead of the scope of the
  field. Scoped services that your own middleware filled for the request (current user, tenant, ...) are now visible to the
  condition; before, they were empty there. In exchange, the fields of a query are resolved in parallel on that one scope, so
  a scoped `DbContext` must not be used directly in a condition: see
  [Things to know about conditional expressions](v4.1.0.md#things-to-know-about-conditional-expressions).
  A rule without a condition no longer goes through the resolution at all.

## Internal

- `FxMap` exposes its internals to `FxMap.EntityFrameworkCore`, `FxMap.MongoDb` and `FxMap.HotChocolate`.
- `FxMapObjectTypeExtension<T>` is now `MapObjectTypeExtension<T>` (internal).

## Documentation

- The XML documentation of `ConditionalExpressionBuilder` states that conditions run concurrently and may run once for each
  mapped object, and what that means for a scoped `DbContext`.

---

## Migration

Nothing to do. If a condition in a HotChocolate schema relied on scoped services being empty, it now sees the request's.
